Part 1 — Verification

核对上课日期有两种方式

DPU 的上课日期由人工逐条录入 SLCM，考勤系统 me.dpu.ac.th 再从 SLCM 取用。 人工录入有出错可能，因此请定期核对。

方式一 从 SLCM 下载报表 5 步
01

登录 SLCM，展开顶部「Professors」菜单

打开 slcm.dpu.ac.th。右上角显示你的工号与姓名即表示已登录。 点击右上方的 Professors，菜单会展开十四个条目。

02

把 Year 改成 2569、Semester 改成 1，点 Search

页面默认带出的是上一个学期（2568 / summer），务必手动修改， 否则查到的是旧数据。Degree 留空即可。

03

Schedule 表格列出该学期全部课程

本学期共四门课，均为 Block 2（短期密集），Study Group 都是 601。 这张表只告诉你「周几上课」，还看不到具体日期。

04

滚动到最下方，点蓝色「Print class schedule」

这个按钮的名称容易误导 —— 它不会打开预览或打印对话框，而是直接下载一个 XLSX 报表文件（报表代号 CSRP06）。 真正的上课日期只存在这份文件里，网页上看不到。

报表服务器不稳定。 首次点击经常返回 504 Gateway Timeout，页面上不会有任何提示，看起来就像没反应。 多点几次、每次间隔约三十秒，通常第二或第三次会成功。
05

打开下载的 XLSX，看最底部的 Remark 区块

报表主体是课程与班级信息，真正要找的东西在最后几行的 Remark： 每门课的完整上课日期，以佛历 dd/mm/2569 格式逐条列出。

方式二 在考勤系统直接查看 1 步
01

打开考勤系统 me.dpu.ac.th，核对上课日期

打开 me.dpu.ac.th 的 Schedule & Check-in。 页面默认就停在 Academic Year 2569, Semester 1。 每门课一行，每一节课一张卡片，从左到右排列，卡片上有日期、时间、教室与刷卡机编号。

「Planned (full term)」的定义就是 SLCM 排定的总节数， 所以这个数字本身也是一个可核对的指标 —— 它应该等于 Remark 列出的日期数量。

注意

由于上课日期是人工逐条输入，系统中显示的日期可能有误，请务必核对，以免实际上了课却没有记录。确实有教师发现，系统内遗漏了两次上课日期。

Part 2 — Make Up Class

在 SLCM 提交补课申请

SLCM 内部把补课归在「临时借用教室申请」之下， 所以表单标题会是 Request form to use a temporary room。 整份表单分为四个区块：你的基本信息、借用申请、要补的是哪一节、补课要用哪间教室。

01

Professors → Make Up Class/Additional Class

从顶部 Professors 菜单倒数第二项进入，网址是 slcm.dpu.ac.th/isdt29。 这是申请列表页，会列出你过往的所有申请记录。

按钮文字容易引起误解：Submit Form 的意思是「填写申请单」， 点击后只是打开空白表单，不会提交任何内容。真正的提交按钮在表单最底部。
02

填写借用申请的基本字段

Purpose 默认就是补课用的第一项。Email 已自动带入，无需修改。

03

选择要补的课程

school year 与 Semester 已默认为 2569 / 1。 course 下拉只会列出你本人该学期的课，选定后 credit 自动带出。

04

指定被取消的那一节：点「Specify the Class Group…」新增一行

选好 Study Group（601 : Track Chinese）之后， Class day-time 与 Instructor 会自动填充，无需手动输入。

05

Study Date 下拉：这里就是那份日期清单

点开 Study Date，系统会列出该课全部实际上课日（公历格式）。 这正是 Part 1 核对过的同一份数据 —— 表单直接读取 SLCM 的排课，不需要你自己输入日期。

这是第三个可交叉验证的来源。 报表、考勤系统、补课表单三边的日期一致，说明数据确实同源。
06

Study Time 会依日期自动收窄

选定日期后再打开 Study Time，系统只会给出那一天实际的时段。 以 KE311 为例，选 2026-10-07（周三）就只出现 13:30 – 16:30； 若选周一的日期则只会出现 09:00 – 12:00。这个机制让你不可能选错时段。

07

指定补课要用的教室：点「Add」新增一行

最后一个区块是实际的教室需求。八个字段，除 Specify Location 外均为下拉菜单。

08

提交，然后在列表页跟踪状态

点击页面最底部的 Submit a request for a temporary room use 提交。 回到列表页后，该条申请会带着 Request No. 出现，状态为 Pending，等待批准。

Pending → Approve ／ Reject ／ Cancel
本文档未涵盖提交之后的画面。 撰写时刻意停在提交前，以免生成一条真实的补课申请。 因此提交后的确认页面、Request No. 的编号格式、以及批准通知的方式尚未记录， 待实际申请时再补充。
